# Yuweiju AFK

1. Read root AGENTS.md, [workflow](../../../docs/agents/workflow.md), and [issue tracker](../../../docs/agents/issue-tracker.md). Automatically read the issue body, comments, state, and native blocking dependencies. Inspect current HEAD/main, affected code and previous improvements before proposing work. Complete the five-item [startup handoff](references/startup.md), drawing known decisions and authorization from this session. Ask together only for genuinely missing human decisions or authorization. Completion: scope, three-client impact, acceptance requirements, human capability and action permissions are explicit.
2. Read [runtime](references/runtime.md). Inspect the actual WSL checkout, branch, HEAD, worktree state, installed dependencies, image, dedicated authentication status and task-owned networks. Keep user changes and existing safety controls. Run `.sandcastle/preflight.py` on the actual task configuration; business-worker repeats it with a read-only login check before starting the coding budget. A network success proves connectivity, not a model request. Completion: preflight passed and required real acceptance capability is ready, or the user explicitly chose candidate-only delivery with outstanding acceptance.
3. Create one task input directory, prompt, and configuration using the runtime's command and path guidance. Use a new `codex/` task branch and an exact local start commit containing the selected runtime. Set requested iteration, coding-total and independent-verification limits. State effective limits and existing model settings before launch. Preserve authentication settings. Set task-specific `evidencePaths` for progress and sanitized check logs; use the [evidence guidance](references/startup.md#预算与逐轮证据). Completion: prompt/configuration/authorization agree, and selected evidence paths exclude credentials and business payloads.
4. Start the existing supervisor only for an authorized coding task. The runtime owns cancellation, cleanup, and result retention. Within the same authorized iteration, correct an obvious command or path error and rerun the affected check. Stop on unresolved decisions, missing required capability, unsafe authorization/resource boundaries, persistent check failure, or supervisor failure. After an incomplete, failed, or cancelled run, do not relaunch or resume without explicit authorization. Command correction does not grant extra iterations, time, dependencies, or scope.
5. Assess supervisor result, exit status, completion signal, task commits, and acceptance checks separately. Missing result, timeout or cancellation remains incomplete even if logs contain COMPLETE. A completion signal without task commits is incomplete. Run applicable independent checks on the exact candidate commit using the existing Windows/Linux verifier. Inspect its diff, per-iteration evidence and resource stop records. Reuse unchanged checks with their source/version; report unexecuted checks. Completion: independent verification is passed or explicitly failed/incomplete, separate from coding, human acceptance and delivery.
6. After independent verification passes, prepare [human acceptance](references/acceptance.md) using the startup authorization. Start already-authorized local services automatically and verify readiness before handing them over. Write `docs/issue#N-executing-report.md` with candidate, checks, human feedback, stop status, evidence and blockers; preserve earlier runs. After required human acceptance passes, use [yuweiju-deliver](../yuweiju-deliver/SKILL.md) within persistent session authorization. Completion: human acceptance and delivery each have an explicit state; missing real acceptance keeps the issue waiting.
7. Review the full Loop once, including failed/cancelled/blocked runs. First check stop records, then evidence, diff and verification. Record concrete proposals, effects, implementation status and missing evidence in the executing report. A retro document request authorizes analysis/documentation only. Implement environment changes through [yuweiju-retro-improve](../yuweiju-retro-improve/SKILL.md) when requested; create a new chat only on an explicit user request. Completion: proposals and completed changes are distinct; business delivery does not wait for maintenance and the review does not recurse.
