# Yuweiju AFK

1. Read root AGENTS.md, [workflow](../../../docs/agents/workflow.md), and [issue tracker](../../../docs/agents/issue-tracker.md). Read the issue body, comments, state, and native blocking dependencies. Confirm scope, acceptance checks, effects on all three clients, and session authorization. Resolve missing decisions before launch. Use existing Matt skills for unclear requirements.
2. Read [runtime](references/runtime.md). Inspect the actual WSL checkout, branch, HEAD, worktree state, installed dependencies, image, and dedicated authentication status. Keep user changes and existing safety controls.
3. Create one task input directory, prompt, and configuration using the runtime's command and path guidance. Use a new `codex/` task branch and an exact local start commit. Set the requested iteration and time limits. State effective limits and existing model settings before launch. Preserve authentication settings.
4. Start the existing supervisor only for an authorized coding task. The runtime owns cancellation, cleanup, and result retention. Within the same authorized iteration, correct an obvious command or path error and rerun the affected check. Stop on unresolved decisions, missing required capability, unsafe authorization/resource boundaries, persistent check failure, or supervisor failure. After an incomplete, failed, or cancelled run, do not relaunch or resume without explicit authorization. Command correction does not grant extra iterations, time, dependencies, or scope.
5. Assess exit status, completion signal, task commits, and acceptance checks separately. A completion signal without task commits is incomplete. Run applicable independent checks on the exact candidate commit. Inspect its diff and recorded resources. Record command directories, exit codes, business results, and unverified items.
6. Write `docs/issue#N-executing-report.md`, including changed files, commit and diff, human review steps, checks, resource stop status, logs, recovery paths, and blockers with remedies. Separate historical host evidence, agent checks, draft review, and exact-commit verification; name unfinished checks. Preserve earlier reports when the issue runs again. Apply session authorization to integration, GitHub writes, real data, and release actions; the AFK request grants no extra scope.
7. After development and verification, use `/retro` once in the host session to review the full Loop. Include failed, cancelled, and blocked runs. First check the resource stop records. Read agent logs, result records, the candidate diff, and verification results. Find changes to the agent environment that can improve the next Loop. Add each proposal to `docs/issue#N-executing-report.md`. Include evidence, effect, proposed action, and implementation status. Record missing evidence and its limits. Keep proposals separate from completed changes. Apply project constraints and session authorization before implementation.
