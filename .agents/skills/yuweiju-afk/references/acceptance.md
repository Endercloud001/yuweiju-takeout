# 人工验收准备与反馈

入口：独立验证已通过，候选和启动前授权已明确。根据当前业务验收项生成一页交接，不复制 issue 专用旧脚本；复用现有 environment 和启动/停止入口。

1. 核对候选提交/产物、隔离与真实验收区别、服务授权和副作用。真实验收涉及登录创建用户、员工写入、缓存或外部调用时列明实际影响与现有授权；原账号由本人输入，不重置原账号制造成功。缺少真实配置仅报告入口和准备方式。
2. 已授权时自动启动本票前端、后端及必要隔离依赖。检查端口，选择可用端口，绑定127.0.0.1；保留其他任务服务。使用精确候选产物，不把旧服务当成新候选。保存本票容器名/PID及所有权、启动日志、候选、URL和停止入口。停止脚本只操作记录的具名资源，保留卷；PID 启停前核对进程/启动时间防止误杀复用 PID。Windows 后台启动用隐藏窗口。
3. 用户交接前检查前端资源、代理请求、后端健康和未登录受保护请求。健康HTTP200不能代替权限断言；页面删除按当前 handler/失败协议验收。验证失败先修正已授权技术问题，不将未就绪服务交给用户。
4. 一页说明列：URL、候选提交、隔离/真实环境、步骤、预期、反馈、日志关联时间、停机方式与约定保留期限。所有必需验收一起说明。合成账号仅用于隔离；真实微信至少确认同账号身份稳定、不同账号数据/访问隔离，具体项由 issue 决定。
5. 保存用户反馈，仅追问缺项。全部必需项通过后按已有交付授权进入 yuweiju-deliver，并按约定停服务；缺少交付权限只补权限。人工等待不计模型编码时间。到期按事先约定停止并给恢复入口；没有到期约定则先收集，不能静默清卷。

完成条件：服务探针和日志就绪；反馈与准确候选对应；所有必需验收分别有“通过/失败/未执行”，隔离通过不能代替真实通过；issue关闭取决于全部必需验收与关闭授权。

用户可用一条回复：

```text
候选版本：…；隔离验收：1通过/2通过；真实验收：通过或未执行；异常：无或步骤、页面提示和操作时间；服务：停止或保留至…
```

本参考描述任务相关服务编排；本次维护不会启动某业务票的人工验收服务，也不声称已有通用服务启动器。
