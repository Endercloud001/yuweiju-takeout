# 后端保留常规分层

2026-10-05，维护者在阅读四种结构的研究与交互讲解后，明确选择继续采用常规分层。后端以 Controller 处理请求、Service 承载业务与事务、Mapper 承载数据访问为基本职责划分，保留 Spring Boot 和 MySQL；不因现代化目标全面改成模块化单体包布局或六边形架构。

本次比较涉及用例编排、模块化单体与六边形结构。保留常规分层符合现有项目规则与维护者已学技术，减少目录和抽象迁移成本；查询难定位、读路径写数据与职责混杂仍需逐项解决，不能由三层目录本身保证。现有 ApplicationService 是否合并或保留按实际职责后续评估，不统一增加第四层，也不只因类名删除已有业务。

决定来源：[Q9 访谈记录](../yuweiju-judgement-grilling.md)、[架构研究](../yuweiju-architecture-research.md)、交互讲解（当时产物当前不在仓库，参考前述研究与访谈）。此 ADR 只记录结构选择，不授权业务改造、数据库操作或发布；维护路线仍是判断建议。
