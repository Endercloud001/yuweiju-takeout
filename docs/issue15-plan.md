# Issue #15: customer session ownership and committed messages

The task starts at confirmed main `4ef7679b203dbfb8832d8f8234bde7afdbfdf7bd`. It implements only the accepted customer service responsibilities in issue #15 and [ADR0001](adr/0001-retain-conventional-backend-layering.md), following [workflow](agents/workflow.md) and [backend](standards/backend.md), [admin](standards/admin.md), [miniapp](standards/miniapp.md) standards. Historical original-database customer evidence is absent; no original writes are repeated. No schema, public API, UI, AI or competition redesign is authorized.

The implementation keeps the existing ApplicationService and thin entity CRUD services. The former becomes the reusable ownership/state boundary, with separate user history/user send/admin send APIs. It accepts identities supplied by trusted authentication, not sender IDs from frames. Named Mapper methods carry latest-open, open-list, history/cursor, last-message and conditional touch/close queries. Primary-key lookup/insert and user batch-primary-key reads remain ordinary CRUD.

Message insert and session touch run within each public Service send method's actual Spring transaction. The session row is locked inside that transaction; close uses the same row lock followed by the named conditional close. Open performs one insert at most, so does not need a multi-write transaction. Existing concurrent first-open creation has no unique constraint and is not claimed solved. Broadcast stays in WebSocket after the proxy returns; transport failure cannot roll back SQL. Typing locks remain ephemeral per-process transport state, with their existing timeout/explicit unlock/disconnect/successful-reply lifecycle.

Implementation steps are chain/consumer inspection, Mapper and Service extraction, protocol delegation, ordinary behavioral tests, compile then complete package, all four existing admin checks, packaged-jar real probe, required mounted Ponytail closeout, scope review, explicit staging and normal local task commit. Repeated runs are check batches within the fixed two-iteration/80-minute shared coding authorization. Independent verification is separate. No push, PR, merge, issue write, deployment or original service is part of this task.
