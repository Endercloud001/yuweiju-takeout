# Domain Docs

本项目采用 single-context：后端、管理端、小程序共享同一套外卖业务概念，技术目录不等于不同业务上下文。

## 探索前读取

读取根目录 `GLOSSARY.md` 和 `docs/adr/` 中涉及本次领域或决策的文档。文件不存在时正常继续；domain-modeling 在术语或决策确实明确后再创建，初始化不创建空词汇表或占位 ADR。

既有接口、数据库及 ExecPlan 文档继续按 AGENTS.md 的领域触发条件读取。Matt 流程补充项目流程；安全、兼容性和三端影响要求仍遵守项目规则。既有计划是历史证据，实施前核对当前代码和用户约束。

## 使用与维护

Issue、重构建议和测试中的业务概念采用 GLOSSARY.md 定义的词汇。新术语先核实代码中的用法，再通过 domain-modeling 明确；与已有 ADR 冲突时说明冲突和重审理由。

未来若出现独立业务上下文，再决定是否引入根目录 GLOSSARY-MAP.md 及上下文词汇表；当前不按三端技术目录拆分。
